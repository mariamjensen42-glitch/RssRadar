# PRD：RssRadar 内容分区（Views）一期

## 项目信息
- Language: 中文
- Programming Language: Kotlin + Jetpack Compose + Room
- Project Name: rssradar-content-views
- 原始需求复述：为 RssRadar 引入 Folo/Feedly 式「分区」——按订阅源内容类型（文章/图片/视频/音频）划分全局内容视图，与用户自定义「分组」互不替代，分区决定内容展示形态。

## 产品定义

### Product Goals
1. 让用户按内容类型快速浏览订阅内容（图片看方图、视频看缩略图、音频看时长），而非一律单列标题。
2. 分区作为独立于「分组」的第二维度，两者可叠加筛选，互不干扰。
3. 复用 ADR-0014 已落地的 `feeds.contentType` 地基，改动最小化，不推翻已 accepted 的架构决策（除非显式确认）。

### User Stories
- 作为读者，我想在主页一键切到「图片」分区，只看图片类源，以便快速刷图。
- 作为读者，我想让视频/音频源在列表中呈现缩略图/时长形态，以便判断是否值得点开。
- 作为读者，我想把「状态 tab（全部/未读…）」与「内容分区」叠加（如「视频 × 未读」），以便精确过滤。
- 作为订阅者，我想看到自己没有订阅源的分区有明确空态提示，以便知道去订阅而不是误以为坏了。
- 作为订阅者，我在 FeedActionScreen 改错了源的类型，能随时改回来，且不影响任何数据。

## 技术规范

### Requirements Pool

**P0（一期必须，一次可交付）**
- 主页内容分区过滤 chip 行（方案 C）：在现有状态 FilterChip 行下新增一行内容类型 chip（全部 / 图片 / 视频 / 音频），文章即默认态、不设「文章」chip。
- 分区 = DB 级过滤：WHERE `feeds.contentType = ?`，与 GitHub issue #74 的分组筛选 WHERE 条件叠加，共用同一分页查询。
- 已有 `ImageGalleryGrid` 保持只在单源列表页出现（维持 ADR-0014 结论），主页图片分区仍为单列卡片流。
- 空分区空态：选中某类型分区但无任何该类型订阅源时，展示引导文案「订阅 XX 类源后在此聚合」（复用现有空态组件，不新增订阅入口逻辑）。
- 类型修正入口沿用现状：FeedActionScreen 可改 `feeds.contentType`，不新增功能。

**P1（二期）**
- 分区感知的卡片形态：视频/音频分区下卡片增加类型标识（时长、播放跳转图标），跳转遵循媒体永不内嵌播放约束。
- 主页两列方图画廊（图片分区）：需先推翻 ADR-0014 的「画廊只在单源页」结论，走新 ADR 后实施。
- 分区状态记忆：记住上次选中的分区，重启恢复。

**P2（远期）**
- 分区未读计数徽标（每分区未读数）。
- 「社媒」独立分区（依赖上游对社媒类型的重新定义，ADR-0014 刻意未设）。
- 通知分区。

### UI Design Draft
- 主页自上而下：FeedTab 状态 chip 行（现有）→ 内容类型 chip 行（新增，横向滚动，选中态与现有 FilterChip 一致）→ 文章列表（现有）。
- 类型 chip 行默认选中「全部」，收起时可考虑只显示非「全部」的激活状态以省垂直空间（细节由实现定）。
- 空分区态：居中图标 + 一句话引导，不阻塞切回「全部」。

### Open Questions（需高城确认）
1. 入口方案确认：推荐方案 C（最小改动、与 #74 WHERE 叠加天然兼容）。方案 A（分区为顶层两级视图）改动大且要动导航结构；方案 B 含「文章」chip 会让默认态多一步选择。是否接受 C？
2. 画廊是否下放主页：一期不做（维持 ADR-0014）；若要做，是否愿意推翻该 ADR 并新写一条？
3. 空分区的另一种交互：选中后「chip 隐藏/置灰」 vs 「显示空态页」——当前推荐后者（可见、可解释），是否接受？
4. 分区计数徽标：一期不做（需要额外聚合查询，成本高收益存疑），P2 是否可接受？
5. 社媒类源（contentType=0 与文章共用）：社媒源出现在「文章」分区是否可接受？ADR-0014 已如此设计，但需产品侧明确表态。
