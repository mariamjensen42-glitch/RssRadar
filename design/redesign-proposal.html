RssRadar UI/UX 重设计提案

基于真机截图（design/screens/01-10）评审 · 目标：达到可公开分发的完成度 · 2026-09-05

一、现状审查（按截图逐页）

页面问题严重度
01 首页① 双层顶部（标题行 + 筛选 chips）占掉 ~140px；② 无图文章显示纯灰色空块，像加载失败而不是"没有图"；③ 卡片高度随图有无跳动，瀑布凌乱；④ 刷新进度"正在刷新 10/709"是裸文本，与 chips 挤在一起；⑤ 底部导航药丸悬浮遮住最后一张卡片，内容没留 bottom padding。P0
02/02b 文章详情① 顶栏 4-5 个线性图标无文字、无可发现性（翻译/分享/字体/AI）；② 底部操作条悬浮遮挡正文最后几行，无 scrim；③ "相关阅读"横向卡片文字被硬截断；④ 正文与 AI 摘要卡之间缺少呼吸空间。P0
03 订阅管理① 顶栏 5 个图标（导入/导出/跳转/排序/添加）全是无标签线性图标，新用户不可能猜中；② 每行一个编辑铅笔 = 噪音；③ "全部标记为已读"放在列表下方裸露位置，极易误触；④ 空分组（0 个订阅）与 708 个订阅的分组视觉权重相同。P0
04 搜索页面 80% 空白，没有"按订阅源浏览 / 热门关键词"等内容托底，首感空洞。P1
05 我的信息量太少，没有版本号、订阅统计、导入 OPML 入口（新用户第一个动作应该在这）。P1
10 分组详情仅 2 篇文章时仍用双列大图网格，空旷；应按数量自适应列表/网格。P1
新用户流程无 onboarding：首次启动若 0 订阅，首页就是灰卡片海。这是"给其他用户使用"的最大缺口。P0
设置页 06-09整体最好：分组清晰、解释文案到位。小问题：分段选择器（列表/卡片/杂志/网格）与主题选择器两套样式；开关尺寸偏大。P2

二、重设计方向（四张关键稿）

原则：不换设计语言（保持现在的紫色强调 + 深色卡片风，这套底子是对的），只修信息架构和空态。图标继续走 lucide 线性描边，与现有偏好一致。

三、落地任务清单（按优先级 + 依赖顺序）

  1. P0 · 首页空态与占位图：无缩略图卡片改为「订阅源首字 / lucide 图标 + 渐变色」占位（按 feedId hash 选色），删除纯灰块；卡片高度统一。（Issue 候选：home-placeholder）
  2. P0 · 首页顶栏合并：标题行保留 搜索 + 标记已读 两个图标，「视图模式/分组筛选」移入右上 ⋯ 或筛选 chips 行尾；刷新进度改为标题下细进度条（LinearProgressIndicator 样式）。
  3. P0 · 新用户 onboarding：检测订阅数为 0 时进入欢迎页（导入 OPML / 推荐榜 / 手动添加 三入口）；「我的」页同步补 OPML 导入入口。完成后才写 onboarding 完成标记。
  4. P0 · 订阅管理信息架构：顶栏收敛为 搜索 + ⋯（导入/导出/全部已读/排序，全部已读加确认对话框）；移除行内铅笔（编辑移到分组详情或长按菜单）；行尾改未读数徽章。
  5. P1 · 详情页操作栏：底部操作条改为实体底栏（非悬浮），正文 Column 加 bottom padding；顶栏只留 返回 + ⋯（翻译/字体/分享/AI 进菜单）。
  6. P1 · 详情页相关阅读：横向卡片文字两行截断加省略号 + 渐隐遮罩，替代当前硬截。
  7. P1 · 搜索页托底：无输入时展示「最近搜索 + 订阅源字母索引 / 推荐关键词」，消除空洞感。
  8. P1 · 分组详情自适应：条目 ≤ 4 时用单列列表布局，> 4 保持网格。
  9. P2 · 设置页一致性：统一分段选择器组件（主题 / 视图模式 / 描述开关共用一套）；开关尺寸对齐 M3 默认。
  10. P2 · 「我的」页充实：顶部加统计条（订阅数 / 未读 / 今日已读，全部来自 DB 真实数字），底部加版本号 + OPML 导入导出。

四、不改的部分（明确保留）

深色主题底色与紫色强调、AI 摘要卡样式（这是产品亮点）、设置页的解释文案写法（「disabled 按钮必须配解释文案」铁律已做得很好）、lucide 线性图标体系、底部药丸导航形态（只修内容遮挡问题）。
