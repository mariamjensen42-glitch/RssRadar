# 推荐流：本机可解释启发式打分，独立 tab 呈现

信息流新增独立的「推荐」tab，从候选池中按透明打分排序产出推荐文章。全部计算在本机完成：无端上 ML 模型、无遥测、无服务端。

## Status

accepted

## Context

对标注的差距项「无 feed 发现/推荐」中的文章推荐部分立项（feed 发现已由 ADR-0010 路由目录覆盖）。核心痛点：上千订阅源、数万篇文章读不过来，时间线排序无法区分"重要"与"新到"。

现有用户信号极其有限：只有 isRead / isStarred / isBookmarked / feed 归属 / 时间戳。没有打开时间、没有停留时长（详情页的"阅读时长"是字数估算，非真实测量）。

## Decision

### 呈现：独立 tab，永不混入时间线

- 信息流新增第五个 tab「推荐」，与 全部/未读/收藏/稍后读 并列。
- **不重排现有列表**：常规信息流严格保持按时间倒序；推荐流是独立的产物，二者互不影响。重排会破坏时间线心智模型，且与分页快照（ADR-0006）冲突。
- **默认开启**，设置里可关（开关有真实读取方）。冷启动退化排序本身有用，不存在"没数据就该隐藏"的状态。
- 冷启动优雅退化：信号不足时按「最近未读、订阅源分组轮转」排序；完全无订阅显示引导空态。tab 永不隐藏。

### 候选池：未读 + 时间窗口

- 候选 = 未读 且 发布时间（`COALESCE(publishedAt, fetchedAt)`，与归档同基准）在窗口内（14 天 = `Recommendation.WINDOW_DAYS` 常量；暂不开设置项——没有真实诉求前不加无读取方的开关）。
- **已读文章永不进推荐**。
- 候选池规模天然受限（未读 + 时间窗），万级以内。

### 信号：新增 lastOpenedAt（最小采集）

- articles 表加 `lastOpenedAt` 列（DB 迁移），每次打开详情页更新。
- 不采集停留时长（Android 前后台切换噪声大，成本收益不成比例）、不做滑动跳过等点击流。
- 与全项目"数据仅存本机"原则一致。

### 打分：透明启发式，三个分量

```
score = w_fresh × 新鲜度 + w_source × 源亲和度 + w_topic × 内容亲和度
```

- **新鲜度**：发布时间的时间衰减函数。
- **源亲和度**：该源文章的历史打开率（按 lastOpenedAt 聚合），带时间衰减——三个月前常看的源不等于现在常看。
- **内容亲和度**：从已打开/收藏/稍后读文章的「标题+摘要」提取 **中文 bigram（二字片段）词袋**（TF-IDF，保留 top 200），与候选文章匹配。不做真分词，不引入分词库（HanLP 等）——中文 bigram 在标题/摘要粒度区分度足够，且零依赖。
- 权重内置，**不暴露给用户调节**；用户的调节手段是"减少此类"（真实负信号闭环），不是假控制感的滑杆。

### 计算：进 tab 实时算，内存分页

- 进 tab 时一次 SQL 拉候选池，Kotlin 算分 + 排序 + 多样性打散，内存分页。
- **不落库 snapshot**：候选池受"未读+窗口"约束规模可控，落库则每次刷新/已读变化都要维护失效，是无底洞。
- **多样性：连续去重窗口**——同一 feed 在推荐流前 N 条（20）内最多 2 条，滑动窗口适配分页。

### 负反馈：单篇「减少此类」

- 推荐卡提供「减少此类」：写负信号，该篇所在 feed 在推荐流中降权（不影响常规信息流与订阅），可撤销。

### 可解释性

- 「我的 → 兴趣画像」页：展示 top 兴趣词与各源亲和度，只读。是"为什么推荐它"的答案，符合"AI 不捏造、数字必须真实"原则——画像仅由真实行为驱动，无预置兴趣类别。

## Alternatives considered

| 方案 | 否决原因 |
| --- | --- |
| 端上 ML（ONNX/TF-Lite 语义排序） | 模型 10MB+、推理框架引入，当前工具链（无 gradle）无法落地验证；效果增益配不上复杂度 |
| 时间线内重排 / 插推荐卡 | 破坏时间线预期；与 ADR-0006 分页快照冲突 |
| 分词库（HanLP / jieba） | 又一个难验证的重依赖；bigram 已够用 |
| 打分落库 snapshot | 失效维护复杂；实时算成本可忽略 |
| SQL 全程排序 | 关键词亲和度无法用 SQL 表达 |

## Consequences

- DB 迁移：articles 加 `lastOpenedAt`（含索引评估）；列表轻量列清单若包含需同步（见 ARTICLE_LIST_COLUMNS 铁律）。
- 兴趣画像（词袋 + 源打开统计）为内存态，打开推荐 tab 时重建；持久化与否由实现定，不构成契约。
- 关键词亲和度的效果依赖文章标题/摘要质量，RSSHub 聚合类源（标题即内容）效果最好；摘要极短的源主要靠源亲和度兜底。
